# 雷管高速检测上位机 — 系统架构说明

面向讲解与交接：说明整机分层、工位工艺、软件模块与和 PLC/相机的边界。

## 1. 一句话目标

对流水线上的雷管完成 **两端外径、长度、表面瑕疵** 检测，按配方综合判定；合格放行，不合格由 PLC 剔除入废料盒，并留下可追溯数据记录。

## 2. 系统分层

```
┌─────────────────────────────────────────────────────────────┐
│ 机电层：机械工装 + 西门子 PLC（节拍 / 硬触发 / 剔除 / 安全）   │
└────────────────────────────┬────────────────────────────────┘
                             │ S7 点位 + 相机硬触发
┌────────────────────────────▼────────────────────────────────┐
│ 视觉层：海康线扫(ST1外径/ST2长度) + 昂纳线扫(ST3瑕疵)         │
└────────────────────────────┬────────────────────────────────┘
                             │ FramePacket
┌────────────────────────────▼────────────────────────────────┐
│ Qt 上位机：采集调度 → 算法 → 槽位对号 → 终判 → 写回/追溯       │
│ Python：measure_od / measure_length / inspect_defect         │
└─────────────────────────────────────────────────────────────┘
```

| 层 | 负责 | 不负责 |
|----|------|--------|
| PLC | 运动节拍、硬触发相机、剔除气缸、急停联锁 | 图像算法、公差判定细节 |
| 相机 | 线扫成像、SDK 取帧 | 业务逻辑 |
| Qt 上位机 | 采图调度、对号、配方终判、HMI、日志 | 直接驱动电机时序 |
| Python 算法 | 尺寸/瑕疵计算 | UI、PLC 握手 |

## 3. 工位工艺流

| 工位 | 设备 | 输出 | 说明 |
|------|------|------|------|
| ST1 | 海康线扫 | D1、D2 (mm) | 圆柱两端外径 |
| ST2 | 海康线扫 | L (mm) | 总长 |
| ST3 | 昂纳线扫 | grade、defect_count | 表面瑕疵等级 |
| ST4 | 软件终判 + PLC | Pass/Fail + FailCode | 汇总 ST1~ST3；NG 入废料盒 |

**对号方式**：PLC 为每发雷管分配 `SlotIndex`（及可选 `ProductSeq`）。上位机用槽位表累计各工位结果，终判工位读取该槽完整记录。缺测或超时按 NG（`TimeoutMissing`）。

### 时序（单发）

1. 工装到位 → PLC **硬触发**对应相机  
2. 同时写软点位：`Trig_STx` + `Slot_STx`  
3. 上位机取帧 → 算法 → 写入 `ProductRecord[slot]`  
4. ST1~ST3 齐备（或 ST4 触发）→ `FinalJudge`  
5. 写回 `PassFail` / `FailCode` / 尺寸回显 → PLC 放行或剔除  
6. 追加 CSV 记录；NG 可选存图  

## 4. 软件模块（仓库路径）

```
config/                 点位表、配方、标定
app/core/               ProductRecord / ProductTracker / FinalJudge / Recipe
app/plc/                IPlcClient / S7Client / ModbusTcpClient / Mock
app/camera/             ICamera / Hik / Onna / CaptureDispatcher
app/algo/               AlgoDispatcher → PythonBridge
app/line/               LineController / ResultTrace
bridge/algo_api.py      C++ 嵌入的稳定算法 API
src/measure_*.py        外径 / 长度 / 瑕疵算法
logs/                   运行时数据记录（见数据文档）
```

无 Snap7 / 相机 SDK 时自动走 **Mock/仿真帧**，可先软件闭环：连接 PLC → 模拟一发 → 查 `logs/results.csv`。

## 5. 多线程与超时（量产路径）

```
UI / PLC 轮询线程
  → CaptureDispatcher 取帧
  → AlgoDispatcher 按工位投递
       ├─ ST1 算法线程（外径）
       ├─ ST2 算法线程（长度）
       └─ ST3 算法线程（瑕疵）
  → ProductTracker（互斥写槽位）→ FinalJudge → 写 PLC / CSV
```

| 机制 | 行为 |
|------|------|
| 工位线程隔离 | 三路 `StationAlgoWorker` 各占一 `QThread`；队列深度默认 2，满则丢帧并记 `AlgoError` |
| 槽位超时 | 首帧入槽启动 `result_timeout_ms` 倒计时；超时未齐结果 → `TimeoutMissing` NG |
| 剔除工位 | PLC `Trig_Judge` 时若仍缺结果 → 强制 NG |
| 模拟一发 | `submitFrameBlocking`，避免异步竞态 |

说明：Python 侧仍受 GIL/`PythonBridge` 全局锁约束，三线程主要保证 **PLC/UI 不被算法卡住**；深度瑕疵上 GPU 后可把 ST3 换成原生推理线程以真正并行。

## 6. 配置入口

| 文件 | 用途 |
|------|------|
| `config/plc_points.json` | S7 DB 点位、故障码、轮询周期 |
| `config/recipes/default.json` | 名义尺寸、公差、瑕疵上限、超时 |
| `config/calib/st*.json` | 各工位像素当量、ROI、阈值 |
